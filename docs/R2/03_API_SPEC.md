# R2 API Specification

## Base transport

R2 uses HTTP on the experimental LAN.

Recommended VM listener:

```text
0.0.0.0:8000
```

Do not hard-code the current DHCP address into application logic.

## Common response media types

- JSON: `application/json`
- artifact: `application/octet-stream`

---

# 1. GET /manifest.json

Returns metadata for the active server release.

The manifest describes the available release. It does **not** contain the device's `current_version`.

The device's current version is device state and belongs in device-side state/reporting. A future OTA Agent compares its local current version with this manifest's `version`.

## 200 response

```json
{
  "schema_version": 1,
  "device_compatible": "atk-dlrk3588",
  "version": "1.1.0",
  "build_id": "r2-dummy-1.1.0",
  "artifact_url": "/update.raucb",
  "sha256": "<64 lowercase hexadecimal characters>",
  "size": 33554432,
  "mandatory": false
}
```

## R2 field rules

### schema_version

Type: integer

R2 value: `1`

Purpose: explicit future schema evolution.

### device_compatible

Type: string

R2 value: `atk-dlrk3588`

Purpose: future compatibility gate. Keep the concept aligned with, but separate from, RAUC's compatible concept.

### version

Type: string

R2 example: `1.1.0`

Purpose: available release version.

R2 does not implement device-side upgrade/downgrade comparison logic.

R3 must freeze the version-ordering policy before implementing Agent upgrade decisions.

### build_id

Type: string

Purpose: distinguish rebuilds/releases and aid evidence tracing.

### artifact_url

Type: string

R2 value: `/update.raucb`

Use a relative URL so DHCP/network addressing is not embedded in release metadata.

### sha256

Type: string

Exactly 64 lowercase hexadecimal characters.

Generated by the server from the active artifact at startup.

Purpose: integrity helper only.

### size

Type: integer

Artifact byte count.

### mandatory

Type: boolean

R2 transports this policy bit but does not implement Agent behavior for it.

## Other responses

### 204 No Content

No active release is configured.

This does **not** mean "the device is already current", because this R2 endpoint is not given the device's current version.

### 503 Service Unavailable

The configured active release is internally inconsistent, for example the artifact disappeared after startup or its size changed.

### 500 Internal Server Error

Unexpected server fault.

# 2. GET /update.raucb

Serves the configured active artifact:

```text
artifacts/versions/1.1.0/update.raucb
```

The on-disk file may be dummy data in R2.

## Full download

Request without `Range`:

`200 OK`

Required headers include:

- `Content-Type: application/octet-stream`
- `Content-Length`
- `Accept-Ranges: bytes`

## Single range

R2 supports one `bytes=` range.

Example:

```text
Range: bytes=0-1023
```

Response:

`206 Partial Content`

Required headers include:

- `Content-Range: bytes 0-1023/<full-size>`
- `Content-Length: 1024`
- `Accept-Ranges: bytes`

## Range limitations

R2 supports single-range only.

Comma-separated multi-range input must be rejected safely and predictably.

Do not delegate untrusted multi-range parsing to the Python-3.8-compatible legacy Starlette `FileResponse` parser.

## Errors

### 400 Bad Request

Malformed or unsupported Range syntax, including R2-unsupported multi-range syntax.

### 404 Not Found

Configured artifact is not present at request time.

### 416 Range Not Satisfiable

A syntactically valid single range is outside the artifact bounds.

Include an appropriate `Content-Range: bytes */<full-size>` header.

### 500 Internal Server Error

Unexpected read/permission/runtime failure.

# 3. POST /device/report

Validates and records a device status event.

R2 does not create a fleet database.

## Request

```json
{
  "device_id": "rk3588-001",
  "current_version": "1.0.0",
  "status": "downloaded",
  "timestamp": "2026-09-02T04:00:00Z"
}
```

## R2 required fields

### device_id

- string
- required
- non-empty
- fixed device identity is required by the stage decision

### current_version

- string
- required
- non-empty

### status

R2 allowed values:

- `idle`
- `checking`
- `downloading`
- `downloaded`
- `error`

These are transport/update-client lifecycle placeholders only. R2 does not implement a device daemon.

R3 may extend this set with Agent/RAUC states.

### timestamp

- RFC 3339 / ISO 8601 timestamp
- timezone must be present
- UTC (`Z`) is preferred

## Successful response

`204 No Content`

The server logs the accepted structured report event.

## Errors

### 400 Bad Request

Malformed JSON.

### 422 Unprocessable Entity

Syntactically valid JSON that fails the report schema.

Examples:

- missing `device_id`
- empty required strings
- unknown status
- invalid timestamp

### 500 Internal Server Error

Unexpected server failure.

# Field staging

## R2 MVP

Manifest:

- schema_version
- device_compatible
- version
- build_id
- artifact_url
- sha256
- size
- mandatory

Report:

- device_id
- current_version
- status
- timestamp

## R3 Agent requirements — reserve conceptually, do not implement now

Potential additions:

- agent_version
- hardware_revision
- serial_number
- boot_slot
- RAUC state/status
- failure reason
- release decision/version-ordering semantics

## R4 production requirements — reserve conceptually, do not implement now

Potential additions:

- release channel
- device group/targeting
- authorization context
- signed metadata
- certificate identity
- TLS/PKI policy
- audit/event persistence
