## 3. Agent-code basis

The accepted extension was derived from the actual implementation in
`RK3588_app/edgeguard-remote-ota-agent/src/reporting.c` and the associated model
definitions, rather than inferred from the R4 documentation.

The unchanged legacy status set is:

```text
idle
checking
downloading
downloaded
error
```

The only status values added by the Agent's extended mapping are:

```text
rollback
success
reboot_pending
installing
```

The optional `agent_state` values are the 15 names returned by `state_name()`:

```text
IDLE CHECK_NETWORK CHECK_UPDATE PRECHECK DOWNLOADING VERIFY_DOWNLOAD
RAUC_VERIFY INSTALLING REBOOT_PENDING BOOT_NEW_SLOT HEALTH_CHECK MARK_GOOD
REPORT_SUCCESS ROLLBACK ERROR
```

The optional `error_code` values exactly match all names generated by
`OTA_ERROR_CODES` in `include/edgeguard_ota/model.h`, from `NONE` through
`TIME_SOURCE_FAILED`; unknown values are rejected.

## 4. Accepted report schema

The existing required legacy fields remain:

| Field | Validation |
|---|---|
| `device_id` | String; existing non-blank validation preserved |
| `current_version` | String; existing non-blank validation preserved |
| `status` | Existing five legacy values plus the four Agent-emitted extended values |
| `timestamp` | Existing timezone-aware datetime validation preserved |

The following fields are additive and optional. If supplied, they must not be
`null` and must satisfy their Agent-derived type/value limits:

| Field | Validation |
|---|---|
| `attempt_id` | Strict string, at most 36 UTF-8 bytes; empty is permitted by the Agent report builder |
| `target_version` | Strict string, at most 255 UTF-8 bytes; empty is permitted by the Agent report builder |
| `build_id` | Strict string, at most 255 UTF-8 bytes; empty is permitted by the Agent report builder |
| `agent_state` | One of the 15 actual Agent state names |
| `error_code` | One of the 29 actual Agent error-code names |
| `timestamp_valid` | Strict JSON boolean |
| `uptime_ms` | Strict JSON integer in `0..9223372036854775807` |

The three optional strings reject ASCII control characters, matching the Agent's
wire validation. Unrelated extra fields remain rejected by Pydantic
`extra="forbid"`. No coercion from strings/numbers/booleans is allowed for the
strict optional scalar fields.

## 5. Structured logging

Accepted extended reports add these keys only when supplied:

```text

```

Representative shape (not runtime evidence):

```json
{"event":"device_report_accepted","device_id":"rk3588-001","device_status":"reboot_pending","attempt_id":"12345678-1234-4234-8234-123456789abc","target_version":"1.1.0","build_id":"rk3588-r4-1.1.0-001","agent_state":"REBOOT_PENDING","error_code":"NONE","response_code":204}
```

Legacy accepted-report log records do not require or synthesize these correlation
keys. Validation logs continue to omit request bodies, preserving the existing
secret-safety behavior.
